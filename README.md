# 진주성: 마지막 가락지

Kotlin + Jetpack Compose + Material 3로 구현한 Android 전용 현장 방탈출 게임 시제품입니다. Flutter를 사용하지 않습니다. 로그인, 게임 서버, 결제, 지도 API 키 없이 동작합니다. 게임 진행은 기기에 저장되며, 실제 지도는 OpenStreetMap 타일을 인터넷으로 불러옵니다.

## Android Studio에서 실행

1. Android Studio Meerkat 이상에서 이 저장소 폴더를 **Open** 합니다.
2. SDK Manager에서 **Android SDK Platform 35**, SDK Build Tools 및 Platform Tools를 설치합니다. Gradle JDK는 내장 JDK 21 또는 JDK 17로 설정합니다.
3. Gradle Sync를 실행합니다. AGP 8.9.2, Gradle 8.11.1, Kotlin 2.1.20을 사용합니다. Wrapper 스크립트와 JAR, 배포 ZIP SHA-256이 포함되어 있습니다.
4. Android 8.0(API 26) 이상의 실제 기기에서 개발자 옵션 → USB 디버깅을 켜고 USB로 연결합니다. 기기의 디버깅 허용 대화상자를 승인합니다.
5. Android Studio에서 `app` 구성과 연결된 기기를 선택하고 Run을 누릅니다.

현장 위치 기능에는 Google Play 서비스가 있는 기기를 권장합니다. Google Play 서비스가 없거나 GPS가 꺼져 있어도 개발 모드로 게임을 진행할 수 있습니다. 권한은 현장 모드 화면의 버튼을 눌렀을 때 요청하며 백그라운드 위치는 요청하지 않습니다.

## APK 생성

Android Studio 메뉴 **Build → Build App Bundle(s) / APK(s) → Build APK(s)** 또는 아래 명령을 사용합니다.

```bash
# SDK 경로는 Android Studio가 local.properties에 자동 기록합니다.
# 명령줄에서는 SDK 설치 경로에 맞춰 ANDROID_HOME을 설정할 수도 있습니다.
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Windows에서는 `gradlew.bat`을 사용합니다. 디버그 APK 경로는 `app/build/outputs/apk/debug/app-debug.apk`입니다. 배포용 APK는 Android Studio의 **Generate Signed App Bundle or APK**에서 본인의 키로 서명하세요. 서명 키는 저장소에 넣지 않습니다.

## 플레이 흐름

- 기본값은 **개발 모드**입니다. 홈 → 여정 시작 → 첫 스팟 → ‘이곳에 도착’ → 퍼즐 정답 → 다음 스팟 순으로 실제 위치 없이 결말까지 진행합니다.
- 공북문, 우물, 촉석루, 의암의 네 기록을 순서대로 수집합니다. 정답이 틀리면 다시 입력할 수 있으며 힌트를 볼 수 있습니다.
- 진행 상황, 수집 기록, 개발 모드 설정은 DataStore에 자동 저장됩니다. 강제 종료 후 이어할 수 있고 설정에서 확인 후 초기화할 수 있습니다.
- **현장 모드**에서는 스팟 목록에 거리를 표시합니다. 대략적 위치만 허용해도 앱을 사용할 수 있지만 도착 판정은 잠깁니다. 정확한 위치 권한을 허용해야 합니다.
- 도착 조건: 스팟 반경 80m 이내, GPS 정확도 50m 이하, 위치 수신 후 60초 이내. 오래된 위치와 대략적 위치는 도착 근거로 사용하지 않습니다.
- 위치 업데이트는 Activity가 보이는 동안만 수행하며 화면을 떠나면 중지합니다. 권한 거부·회수·위치 요청 실패 시 안내를 표시합니다.

## 실제 지도와 걷기 테스트

1. 스마트폰에 APK를 설치하고 GPS와 인터넷을 켭니다. 홈에서 **현장 지도 / 걷기 테스트**를 엽니다.
2. **위치 권한 요청 / 갱신**을 누르고 ‘앱 사용 중’ 및 **정확한 위치**를 허용합니다. 대략적 위치는 지도 표시만 가능하며 도착 판정은 잠깁니다.
3. 지도에서 내 위치와 파란 GPS 오차 원, 네 스팟 마커를 확인합니다. 마커를 누르거나 이전/다음 스팟으로 목적지를 선택할 수 있습니다. ‘선택 스팟 보기’는 목적지로, ‘내 위치 따라가기’는 현재 위치로 지도를 이동합니다.
4. 진주성 밖에서도 테스트하려면 안전한 야외 장소에서 **현재 위치를 테스트 스팟으로 지정**을 누릅니다. 주황색 80m 범위가 생깁니다. 아래 패널은 위로 스크롤해 테스트 버튼을 볼 수 있습니다.
5. GPS 오차 원까지 80m 범위 밖으로 나갈 만큼 걸어갑니다(오차가 10m라면 중심에서 90m 초과). ‘범위 밖 이동 확인’ 표시 후 80m 안으로 돌아오면 **걷기 테스트 완료**가 표시됩니다. 임시 스팟은 게임 진행을 변경하지 않고, 화면을 떠나면 없어질 수 있습니다.
6. 실제 게임을 테스트하려면 설정에서 **개발 모드를 끄고**, 현장 지도에서 첫 스팟을 선택해 이동합니다. 정확하고 최신인 GPS가 80m 안을 가리키면 **도착 확인 완료**와 ‘퍼즐 열기’가 활성화됩니다. 퍼즐 화면에서도 동일한 조건으로 검사하므로 범위를 벗어나거나 GPS가 오래되면 다시 잠깁니다.

지도 원은 직선 거리 반경이며 길 안내나 안전한 보행 경로가 아닙니다. 현재 스팟 좌표는 근사값이므로 실제 관람 동선에서 답사 후 보정해야 합니다. 강변·의암 위험 구역으로 들어가지 마세요. GPS 흔들림으로 거리는 변할 수 있습니다.

네트워크 연결이 없으면 지도는 캐시된 타일만 보이거나 빈 화면일 수 있습니다. GPS 도착 판정과 로컬 게임 진행은 타일 로딩과 독립적입니다. OpenStreetMap 기본 타일 서버를 사용하고 화면에 저작권 링크를 표시합니다. 지도 캐시는 앱의 내부 캐시 디렉터리에 저장하며 대량 다운로드/오프라인 지역 사전 저장은 구현하지 않았습니다. 현재 위치를 별도 서버로 전송하지 않지만, 지도 서버에는 타일 요청 영역과 IP가 전달됩니다. 타일 서버 사용 정책: https://operations.osmfoundation.org/policies/tiles/ .

### 에뮬레이터에서 이동 재현

Google Play 서비스가 있는 Android 에뮬레이터에서 Extended Controls → Location → Single points / Routes를 이용할 수 있습니다. 예를 들어 첫 스팟 `(35.1929, 128.0827)`을 선택한 다음 위도를 `35.1940`으로 옮겨 범위 밖 상태를, `35.1932`로 옮겨 범위 안 상태를 확인합니다. 위치의 정확도/갱신 조건도 충족해야 합니다. 모의 이동은 실제 기기의 GPS, 권한 변경, 지도 타일 동작에 대한 현장 테스트를 대신하지 않습니다.

## 구조

- `MainActivity.kt`: Navigation Compose 화면, Material 3 UI, 사용 중 위치 권한과 Fused Location Provider
- `Game.kt`: 네 스팟의 창작 스토리와 퍼즐, 거리 계산, ViewModel + StateFlow, DataStore
- `FieldMapScreen.kt`: OpenStreetMap 지도, 현재 위치/오차/도착 범위 표시, 임시 걷기 테스트 스팟
- `Arrival.kt`: 지도와 퍼즐에서 공유하는 거리·정확도·최신성 기반 도착 판정
- `GameTest.kt`, `ArrivalTest.kt`: 거리 단위, 정답 처리, 도착 경계/권한/오차/오래된 위치 검증

좌표는 **현장 답사 전 근사 좌표**이며 특히 우물 위치는 현장 확인과 보정이 필요합니다. 실제 운영 전 안전한 공개 관람 동선에서 좌표와 판정 반경을 검증하세요. 의암·강변 위험 구역으로 접근할 필요가 없습니다. 스토리와 퍼즐은 역사에서 영감을 받은 창작이며 역사적 사실을 재현하는 교육 자료가 아닙니다.

## 수동 검증 체크리스트

1. 위치 권한 없이 개발 모드에서 네 퍼즐과 결말을 완료합니다.
2. 두 번째 기록까지 진행 후 앱을 종료·재실행해 진행과 모드가 유지되는지 확인합니다.
3. 현장 모드에서 권한 거부, 대략적 위치, 정확한 위치를 각각 테스트합니다. 대략적 위치에서는 도착이 허용되지 않아야 합니다.
4. GPS를 끄거나 권한을 시스템 설정에서 회수한 후 복귀하여 안내와 재요청을 확인합니다.
5. 앞 스팟 완료 전 다음 스팟이 잠기는지, 초기화 취소 시 기록이 보존되는지 확인합니다.

## 클라우드 검증 상태

JDK 21, Android SDK Platform 35, Build Tools 35.0.0, Platform Tools를 클라우드의 쓰기 가능한 경로에 설치했습니다. Gradle 배포 ZIP/Wrapper JAR, JDK 및 Android SDK 다운로드는 공식 체크섬으로 검증했습니다. APK 빌드와 6개 JVM 테스트(게임 3개, 도착 판정 3개)가 통과했습니다. `lintDebug`도 오류 없이 통과했으며 일부 권고성 경고는 남아 있습니다. 이 결과는 실제 지도 화면이나 GPS 현장 테스트가 완료되었다는 뜻은 아닙니다. 실제 기기 실행과 위 걷기 체크리스트는 Android 기기에서 수행해야 합니다.

클라우드에서 재빌드할 때는 보존된 도구/SDK/인증서/프록시를 사용하는 다음 명령을 실행합니다:

```bash
python /workspace/jinju-tools/run-android-build.py :app:assembleDebug :app:testDebugUnitTest
```

Android Studio에서는 별도 클라우드 도구 없이 위의 일반 Gradle 명령을 사용하면 됩니다.
