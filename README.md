# 진주성: 마지막 가락지

Kotlin + Jetpack Compose + Material 3로 구현한 Android 전용 현장 방탈출 게임 시제품입니다. Flutter를 사용하지 않습니다. 로그인, 게임 서버, 결제, 지도 API 키 없이 동작합니다. 게임 진행은 기기에 저장되며, 실제 지도는 OpenStreetMap 타일을 인터넷으로 불러옵니다.

## 스토리: 논개에게 옥가락지를 전달하는 부탁

**“그녀가 부탁한 것은 가락지였다. 그 이유는 마지막에야 알게 되었다.”**

현재의 진주성 방문자가 첫 장소에서 1593년의 기억과 논개의 부탁을 만납니다. 옥가락지를 찾아 촉석루까지 가져다 달라는 부탁을 따라 전달자의 단서를 찾고, 화면 속 경비의 암호를 풀어 보관함을 엽니다. 마지막 안전한 관람 지점에서 가락지를 전달할 때 그 의미를 알아차립니다. 순국을 직접 조작하지 않고 남강 풍경과 짧은 이야기로 마무리합니다.

이 게임은 **옥가락지 전승을 바탕으로 재구성한 창작**입니다. 옥이라는 재질을 확정된 역사적 사실로 제시하지 않습니다. 전달 부탁, 보관인, 경비 잠입, 퍼즐은 창작 설정입니다. 의기사는 후대에 세워진 추모 공간이며 현재에서 과거의 기억이 열리는 지점으로 사용합니다. 실제 시설물 안에 몰래 들어갈 필요가 없습니다.

답사 전 후보 스팟 순서: **입구 인근 → 성벽 안쪽 → 촉석루 주변 → 의기사 인근 → 남강 관람 지점**. 좌표는 현장 답사와 공개 관람 동선 확인 후 보정해야 합니다. 의암 바위나 위험한 강변으로 접근하지 않습니다.

새 스토리는 이전 네 기록 이야기와 별도의 DataStore 진행 키를 사용합니다. 업데이트 후 새 이야기는 처음부터 시작하며 기존 개발 모드 설정은 유지됩니다. 이전 진행 데이터는 삭제하지 않습니다.

## Android Studio에서 실행

1. Android Studio Meerkat 이상에서 이 저장소 폴더를 **Open** 합니다.
2. SDK Manager에서 **Android SDK Platform 35**, SDK Build Tools 및 Platform Tools를 설치합니다. Gradle JDK는 내장 JDK 21 또는 JDK 17로 설정합니다.
3. Gradle Sync를 실행합니다. AGP 8.9.2, Gradle 8.11.1, Kotlin 2.1.20을 사용합니다. Wrapper 스크립트와 JAR, 배포 ZIP SHA-256이 포함되어 있습니다.
4. Android 8.0(API 26) 이상의 실제 기기에서 개발자 옵션 → USB 디버깅을 켜고 USB로 연결합니다. 기기의 디버깅 허용 대화상자를 승인합니다.
5. Android Studio에서 `app` 구성과 연결된 기기를 선택하고 Run을 누릅니다.

현장 위치 기능에는 Google Play 서비스가 있는 기기를 권장합니다. Google Play 서비스가 없거나 GPS가 꺼져 있어도 개발 모드로 게임을 진행할 수 있습니다. 권한은 현장 모드 화면의 버튼을 눌렀을 때 요청하며 백그라운드 위치는 요청하지 않습니다.

## APK 생성

Android Studio 메뉴 **Build → Build App Bundle(s) / APK(s) → Build APK(s)** 또는 아래 명령을 사용합니다.

```bash
# SDK 경로는 Android Studio가 local.properties에 자동 기록합니다.
# 명령줄에서는 SDK 설치 경로에 맞춰 ANDROID_HOME을 설정할 수도 있습니다.
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Windows에서는 `gradlew.bat`을 사용합니다. 디버그 APK 경로는 `app/build/outputs/apk/debug/app-debug.apk`입니다. 배포용 APK는 Android Studio의 **Generate Signed App Bundle or APK**에서 본인의 키로 서명하세요. 서명 키는 저장소에 넣지 않습니다.

## 플레이 흐름

- 기본값은 **개발 모드 + 지도 버튼 이동**입니다. 홈 → 여정 시작 / 이어하기 → 프롤로그 스토리 → 다음 → 지도 이동 → 자동 도착 이야기 → 임무 시작 → 퀴즈 정답 → 임무 완료 후 스토리 → 진행 → 다음 스팟 지도 순으로 실제 위치 없이 결말까지 진행합니다. 지도에서 버튼 이동을 끄면 기존 ‘이곳에 도착’ 버튼도 사용할 수 있습니다.
- 입구의 나침반, 성벽 안내판 카메라 OCR, 촉석루의 역사 순서 카드, 의기사 인근의 잠금 고리, 관람 지점의 가락지 전달을 순서대로 풉니다. 정답이 틀리면 다시 입력할 수 있으며 힌트를 볼 수 있습니다.
- 진행 상황, 수집 기록, 개발 모드 설정은 DataStore에 자동 저장됩니다. 강제 종료 후 이어할 수 있고 설정에서 확인 후 초기화할 수 있습니다.
- **현장 모드**에서는 스팟 목록에 거리를 표시합니다. 대략적 위치만 허용해도 앱을 사용할 수 있지만 도착 판정은 잠깁니다. 정확한 위치 권한을 허용해야 합니다.
- 도착 조건: 스팟 반경 80m 이내, GPS 정확도 50m 이하, 위치 수신 후 60초 이내. 오래된 위치와 대략적 위치는 도착 근거로 사용하지 않습니다.
- 위치 업데이트는 Activity가 보이는 동안만 수행하며 화면을 떠나면 중지합니다. 권한 거부·회수·위치 요청 실패 시 안내를 표시합니다.

## 역사와 휴대폰 조작 미션

텍스트 정답 입력 대신 각 장소에서 다른 방식으로 조작합니다.

| 스팟 | 조작 | 역사 단서 |
| --- | --- | --- |
| 입구 | 화면 나침반을 돌려 북쪽 선택 | 공북문은 북쪽 문 |
| 성벽 | 실제 안내판 촬영 → 한국어 OCR → 기능 선택 | 성벽의 방어 기능 |
| 촉석루 | 위/아래 버튼으로 사건 카드 배열 | 1592 제1차 전투 → 1593 제2차 전투 → 후대 추모 |
| 의기사 | 세 잠금 고리를 돌려 시기·인물·목적 선택 | 후대 · 논개 · 추모 |
| 관람 지점 | 슬라이더로 가락지를 옮겨 전달 | 가락지 전승과 창작 임무의 구분 |

카메라는 시스템 카메라 앱을 열어 고해상도 사진을 받아옵니다. 앱 자체에는 CAMERA/저장소 권한을 추가하지 않았고, 촬영은 별도 카메라 앱의 권한 정책을 따릅니다. `FileProvider`는 앱 캐시의 `camera/` 경로만 공유합니다. 사진은 `cache/camera/mission-sign.jpg` 한 장을 덮어쓰며 앨범이나 서버에 저장하지 않습니다. 캐시 삭제/앱 삭제 시 사진도 없어집니다.

한국어 OCR은 앱에 포함한 ML Kit 모델을 사용하므로 모델 다운로드용 API 키나 런타임 네트워크가 필요 없습니다. 인식 결과에서 ‘진주성’, ‘성벽’, ‘성곽’ 중 하나를 찾으면 관찰 퀴즈 선택지가 활성화됩니다. 이 키워드 검사는 사진의 진위나 실제 방문, 글의 역사적 정확성을 검증하지 않습니다. 도착 판정은 계속 GPS/개발 모드 위치로 별도 확인합니다. 촬영 취소, 카메라 앱 없음, OCR 실패, 관계없는 글은 임무를 자동 완료하지 않습니다. 사진 재촬영 및 글자 재인식 버튼으로 다시 시도할 수 있습니다.

개발 모드에는 **안내판 연습 글 사용** 버튼이 있습니다. 실제 OCR 결과와 구분해 표시하며 현장 모드에서는 제공하지 않습니다. 카메라와 한국어 OCR 품질은 아직 실제 기기/현장 안내판에서 검증하지 않았습니다. 가까이서 글자가 선명하게 보이도록 촬영하되 시설물과 관람 동선은 지켜주세요.

역사 자료 안내는 국립진주박물관(https://jinju.museum.go.kr/)과 한국민족문화대백과사전 의기사 항목(https://encykorea.aks.ac.kr/Article/E0013009)을 연결합니다. 이 구현 과정에서 의기사 페이지 직접 요청은 HTTP 403으로 접근하지 못했으며, 특정 현장 안내판의 글이나 인식 정확도를 확인했다고 주장하지 않습니다. 퀴즈의 경비·보관함·전달 임무는 창작입니다.

## 화면 디자인

밝은 종이색 배경과 짙은 녹색 글자, 16~17sp 본문과 25~28sp 줄 간격을 사용합니다. 홈은 제목·현재 목적지·진행률·주요 버튼을 우선 표시하며 긴 전승 안내는 접어서 제공합니다. 전체 화면 지도는 유지하고 임무와 역사 단서는 카드로 구분합니다.

## 여정 시작 / 이어하기 흐름

홈에서 **여정 시작 / 이어하기**를 누르면 먼저 프롤로그 스토리가 나옵니다. 이어하기에서는 수집한 기록과 다음 목적지를 함께 안내합니다. **다음**을 누르면 지도 화면으로 이동합니다.

지도에서 현재 진행할 스팟의 80m 안으로 들어오면 이야기 이벤트가 자동으로 나타납니다. **임무 시작**를 눌러 방탈출 퀴즈를 풀고, 정답 저장이 완료되면 **임무 완료 후 이야기** 화면으로 자동 이동하고 획득한 기록, 후속 스토리, 다음 목적지가 표시됩니다. **진행**을 누르면 다음 목적지가 선택된 전체 화면 지도로 돌아갑니다. 마지막 퀴즈의 후속 스토리에서 **진행**을 누르면 결말이 나옵니다. 모든 기록이 완료된 뒤 홈 버튼은 **결말 다시 보기**가 됩니다.

## 집에서 지도 방향 버튼으로 플레이

1. 개발 모드를 켜고 홈 → **현장 지도 / 걷기 테스트**를 엽니다. **지도에서 버튼으로 이동**은 기본으로 켜져 있습니다. GPS나 위치 권한 없이 공북문 북쪽 약 170m에서 시작합니다(지도 타일에는 인터넷이 필요합니다).
2. 지도 위 하단의 **북/남/서/동** 버튼으로 한 번에 **10m 또는 25m** 이동합니다. 모의 플레이어 마커, 거리와 도착 판정이 같이 바뀝니다. 현재 진행할 스팟 안으로 들어가면 이야기 이벤트가 자동으로 나타납니다.
3. 첫 스팟에서는 **25m**를 선택하고 **남 ↓**을 네 번 누르면 80m 안으로 들어가면 지도 위에 **이야기 시작** 이야기 이벤트가 자동으로 뜹니다. **임무 시작**를 누르면 퍼즐로 이어집니다. 범위 밖에서는 이벤트가 발생하지 않으며 모의 위치는 퍼즐 화면에서도 공유됩니다.
4. 정답을 입력한 뒤 지도로 돌아와 다음 스팟을 선택합니다. **선택 스팟 출발점**을 누르면 그 스팟 북쪽 약 170m로 이동하므로 각 스팟의 경계 진입을 쉽게 테스트할 수 있습니다. 다음 목적지로 직접 버튼 이동해도 됩니다.
5. **현재 위치를 테스트 스팟으로 지정**을 누르고 방향 버튼으로 범위 밖 이동 → 복귀도 테스트할 수 있습니다. 지도에서 모의 위치를 표시하며 실제 기기의 GPS 위치는 변경하지 않습니다.

방향 버튼은 개발 모드에서만 표시됩니다. 개발 모드를 끄면 실제 GPS와 실제 권한으로만 판정합니다. 모의 좌표와 버튼 이동 설정은 화면 이동/화면 회전 시 유지되지만 영구 진행 기록과는 별개입니다. 기본 모의 오차는 5m이고 가상 위치는 최신 상태로 취급합니다. 실제 GPS의 오차/최신성 제한은 그대로 유지합니다.

### 전체 화면 지도

지도는 앱 화면 전체를 채웁니다. 상단의 반투명 카드에는 현재 목적지와 거리, 하단에는 모의 이동 버튼과 OpenStreetMap 저작권 링크가 지도 위에 표시됩니다. 스팟 선택, 위치 권한, 버튼 이동 설정, 임시 걷기 테스트는 **스팟 / 테스트 설정** 버튼의 시트에서 사용할 수 있습니다.

스팟 이벤트 상태는 마지막으로 이벤트가 나온 스팟 번호를 저장합니다. 미완료 스팟에서 정확하고 최신인 위치로 반경 80m 밖으로 나간 것이 확인되면 이벤트를 다시 활성화하고, 재진입할 때 자동으로 엽니다. GPS 손실이나 오래된 위치는 이탈로 처리하지 않습니다. 이전 지도 화면의 상태가 복원되어도 다음 스팟의 도착 이벤트는 막히지 않습니다. 각 퀴즈 이후 후속 스토리의 **진행** 버튼은 다음 지도 화면을 새로 열어 이전 퀴즈/이벤트 상태를 섞지 않습니다.

## 실제 지도와 걷기 테스트

1. 스마트폰에 APK를 설치하고 설정에서 개발 모드를 끈 뒤 GPS와 인터넷을 켭니다. 홈에서 **현장 지도 / 걷기 테스트**를 엽니다.
2. **위치 권한 요청 / 갱신**을 누르고 ‘앱 사용 중’ 및 **정확한 위치**를 허용합니다. 대략적 위치는 지도 표시만 가능하며 도착 판정은 잠깁니다.
3. 지도에서 내 위치와 파란 GPS 오차 원, 다섯 스팟 마커를 확인합니다. 마커를 누르거나 이전/다음 스팟으로 목적지를 선택할 수 있습니다. ‘선택 스팟 보기’는 목적지로, ‘내 위치 따라가기’는 현재 위치로 지도를 이동합니다.
4. 진주성 밖에서도 테스트하려면 안전한 야외 장소에서 **현재 위치를 테스트 스팟으로 지정**을 누릅니다. 주황색 80m 범위가 생깁니다. 상단 **스팟 / 테스트 설정**을 누르고 설정 창을 스크롤하면 테스트 버튼을 볼 수 있습니다.
5. GPS 오차 원까지 80m 범위 밖으로 나갈 만큼 걸어갑니다(오차가 10m라면 중심에서 90m 초과). ‘범위 밖 이동 확인’ 표시 후 80m 안으로 돌아오면 **걷기 테스트 완료**가 표시됩니다. 임시 스팟은 게임 진행을 변경하지 않고, 화면을 떠나면 없어질 수 있습니다.
6. 실제 게임을 테스트하려면 설정에서 **개발 모드를 끄고**, 현장 지도에서 첫 스팟을 선택해 이동합니다. 정확하고 최신인 GPS가 80m 안을 가리키면 **이야기 시작** 이야기 이벤트가 지도 위에 자동 표시됩니다. **임무 시작**로 퍼즐을 시작합니다. 퍼즐 화면에서도 동일한 조건으로 검사하므로 범위를 벗어나거나 GPS가 오래되면 다시 잠깁니다.

지도 원은 직선 거리 반경이며 길 안내나 안전한 보행 경로가 아닙니다. 현재 스팟 좌표는 근사값이므로 실제 관람 동선에서 답사 후 보정해야 합니다. 강변·의암 위험 구역으로 들어가지 마세요. GPS 흔들림으로 거리는 변할 수 있습니다.

네트워크 연결이 없으면 지도는 캐시된 타일만 보이거나 빈 화면일 수 있습니다. GPS 도착 판정과 로컬 게임 진행은 타일 로딩과 독립적입니다. OpenStreetMap 기본 타일 서버를 사용하고 화면에 저작권 링크를 표시합니다. 지도 캐시는 앱의 내부 캐시 디렉터리에 저장하며 대량 다운로드/오프라인 지역 사전 저장은 구현하지 않았습니다. 현재 위치를 별도 서버로 전송하지 않지만, 지도 서버에는 타일 요청 영역과 IP가 전달됩니다. 타일 서버 사용 정책: https://operations.osmfoundation.org/policies/tiles/ .

### 에뮬레이터에서 이동 재현

Google Play 서비스가 있는 Android 에뮬레이터에서 Extended Controls → Location → Single points / Routes를 이용할 수 있습니다. 예를 들어 첫 스팟 `(35.1929, 128.0827)`을 선택한 다음 위도를 `35.1940`으로 옮겨 범위 밖 상태를, `35.1932`로 옮겨 범위 안 상태를 확인합니다. 위치의 정확도/갱신 조건도 충족해야 합니다. 모의 이동은 실제 기기의 GPS, 권한 변경, 지도 타일 동작에 대한 현장 테스트를 대신하지 않습니다.

### 자동 도착 이벤트 동작

마커 선택 여부와 관계없이 **현재 진행할 다음 스팟**의 80m 범위에 들어오면 지도 위에 이야기 이벤트가 자동으로 나타납니다. 실제 GPS와 버튼 이동 모두 같은 도착 판정을 사용합니다. 지도 화면이 활성화된 때만 이벤트를 표시하며 대략적 위치·오래된 위치·큰 GPS 오차에서는 발생하지 않습니다.

- 이벤트에서 **임무 시작**를 누르면 해당 퍼즐로 이동합니다. 정답을 맞혀야 진행 기록이 저장됩니다.
- **지도에 머무르기**로 닫으면 범위 안에 머무르는 동안에는 반복 팝업이 뜨지 않습니다. 퀴즈를 아직 완료하지 않았다면 80m 밖으로 나갔다가 들어왔을 때 이벤트가 다시 자동으로 열립니다. 필요하면 **도착 이벤트 다시 보기**로도 열 수 있습니다. 완료한 스팟은 재진입해도 자동으로 열리지 않습니다.
- 이전 챕터가 완료되기 전에는 뒤쪽 스팟 이벤트가 발생하지 않으며, 수집이 끝난 스팟은 재방문해도 자동 이벤트가 발생하지 않습니다. 다음 챕터를 해금할 때 이미 그 범위 안이라면 해당 이벤트가 바로 표시될 수 있습니다.
- 이야기 창이 열린 뒤 도착 조건을 잃으면 해독 버튼이 잠깁니다. 위치를 확인한 후 다시 진행하세요.

## 구조

- `MainActivity.kt`: Navigation Compose 화면, Material 3 UI, 사용 중 위치 권한과 Fused Location Provider
- `Game.kt`: 다섯 스팟의 창작 스토리와 퍼즐, 거리 계산, ViewModel + StateFlow, DataStore
- `FieldMapScreen.kt`: OpenStreetMap 지도, 현재 위치/오차/도착 범위 표시, 임시 걷기 테스트 스팟
- `Arrival.kt`: 지도와 퍼즐에서 공유하는 거리·정확도·최신성 기반 도착 판정
- `GameTest.kt`, `ArrivalTest.kt`: 거리 단위, 정답 처리, 도착 경계/권한/오차/오래된 위치 검증

좌표는 **현장 답사 전 근사 좌표**이며 특히 마지막 관람 지점은 실제 안전한 공개 동선에서 확정해야 합니다. 실제 운영 전 안전한 공개 관람 동선에서 좌표와 판정 반경을 검증하세요. 의암·강변 위험 구역으로 접근할 필요가 없습니다. 스토리와 퍼즐은 역사에서 영감을 받은 창작이며 역사적 사실을 재현하는 교육 자료가 아닙니다.

## 수동 검증 체크리스트

1. 위치 권한 없이 개발 모드에서 다섯 퍼즐과 결말을 완료합니다.
2. 두 번째 기록까지 진행 후 앱을 종료·재실행해 진행과 모드가 유지되는지 확인합니다.
3. 현장 모드에서 권한 거부, 대략적 위치, 정확한 위치를 각각 테스트합니다. 대략적 위치에서는 도착이 허용되지 않아야 합니다.
4. GPS를 끄거나 권한을 시스템 설정에서 회수한 후 복귀하여 안내와 재요청을 확인합니다.
5. 앞 스팟 완료 전 다음 스팟이 잠기는지, 초기화 취소 시 기록이 보존되는지 확인합니다.
6. 카메라 촬영 성공/취소, 카메라 앱 없음, 흐린 글자/관계없는 글, 화면 회전 후 재인식을 확인합니다. 현장 모드에서 연습 글 버튼이 없고 실제 사진 OCR 전 선택지가 잠기는지 확인합니다.
7. 첫 도착 이벤트를 닫고 25m 이동 버튼으로 80m 밖에 나갔다가 돌아와 자동 재실행을 확인합니다. 완료한 스팟에서는 반복되지 않아야 합니다.

## 클라우드 검증 상태

JDK 21, Android SDK Platform 35, Build Tools 35.0.0, Platform Tools를 클라우드의 쓰기 가능한 경로에 설치했습니다. Gradle 배포 ZIP/Wrapper JAR, JDK 및 Android SDK 다운로드는 공식 체크섬으로 검증했습니다. APK 빌드와 19개 JVM 테스트(게임 3개, 도착 판정 3개, 버튼 이동 2개, 도착 이벤트 8개, 미션 조작 규칙 3개)가 통과했습니다. `lintDebug`도 오류 없이 통과했으며 일부 권고성 경고는 남아 있습니다. 이 결과는 실제 지도 화면이나 GPS 현장 테스트가 완료되었다는 뜻은 아닙니다. 실제 기기 실행과 위 걷기 체크리스트는 Android 기기에서 수행해야 합니다.

클라우드에서 재빌드할 때는 보존된 도구/SDK/인증서/프록시를 사용하는 다음 명령을 실행합니다:

```bash
python /workspace/jinju-tools/run-android-build.py :app:assembleDebug :app:testDebugUnitTest
```

Android Studio에서는 별도 클라우드 도구 없이 위의 일반 Gradle 명령을 사용하면 됩니다.
